# Универсальный отчёт Битрикс24

## 1. Общая характеристика

Файл `Универсальный отчёт.xls` — старая выгрузка Битрикс24, далее «Б24 УО».

Несмотря на расширение `.xls`, файл является HTML-документом с одной таблицей, а не бинарной книгой Excel BIFF.

| Параметр | Значение |
| --- | --- |
| Таблиц | 1 HTML-таблица |
| Строк | 2 452, включая заголовок |
| Строк данных | 2 451 |
| Колонок | 113 |
| Заголовок | первая строка `<thead>` |
| Формулы Excel | нет |
| Объединения | нет |

Единица строки — сделка Б24. Расчётные поля уже вычислены на стороне отчёта и выгружены как готовые значения.

## 3. Расчётные поля старого УО

Формулы ниже описывают историческую логику отчёта. Они полезны для проверки, но при реализации следует учитывать дату сделки, валюту и схему финансовой карты.

### 3.1. Оплата поставщику

Для валютной сделки:

```text
Оплата поставщику =
    Всего к оплате поставщику
    × средний курс сделки на даты платежей
```

Для рублевой сделки используется рублёвая сумма.

### 3.2. Прибыль

```text
Прибыль = Сумма продажи - Нетто в рублях
```

В новой сырой выгрузке эквивалентное значение надёжнее восстанавливается по компонентам:

```text
Дополнительная выгода + Сервисный сбор + Комиссия
```

### 3.3. Прибыль без НДС

Историческое правило УО:

- схема `Оказание услуг` и ставка «Без НДС/0%» → `Прибыль`;
- схема `Оказание услуг` с облагаемой ставкой → `Прибыль / коэффициент НДС`;
- прочие облагаемые схемы → `Прибыль / коэффициент НДС`;
- рассчитывается только при положительной прибыли.

С 01.01.2026 коэффициент для ставки 22% равен `1,22`. Для предыдущих периодов нельзя применять его безусловно.

### 3.4. Компоненты без НДС

```text
Комиссия без НДС = Комиссия / 1,22
Сервисный сбор без НДС = Сервисный сбор / 1,22
```

Для дополнительной выгоды документация УО содержит историческое правило деления на коэффициент НДС, но фактическое сравнение старого и нового отчёта 2026 года показывает, что в итоговой восстановленной прибыли дополнительная выгода учитывается без деления:

```text
Прибыль без НДС =
    Дополнительная выгода
    + (Сервисный сбор + Комиссия) / 1,22
```

Это правило следует считать подтверждённым фактическими данными, а историческое описание — зависимым от схемы/версии отчёта.

### 3.5. Нетто в рублях

```text
Валютная сделка:
    (Нетто в валюте + Сбор поставщика в валюте)
    × средний курс ЦБ

Рублевая сделка:
    Нетто + Сбор поставщика
```

### 3.6. Сумма НДС

```text
Сумма НДС =
    (Комиссия - Комиссия без НДС)
    + (Дополнительная выгода - Дополнительная выгода без НДС)
    + (Сервисный сбор - Сервисный сбор без НДС)
```

Исторический отчёт использовал округлённые составляющие.

### 3.7. Возвраты

```text
Прибыль РС ТЛС с учетом возврата =
    Штраф клиенту РС ТЛС
    + Остаток сбора РС ТЛС

Удержал поставщик =
    Штраф от поставщика
    + Сбор поставщика на возврат

Сумма продажи после возврата =
    Сумма входящих платежей
    - Сумма транзакций возврата клиенту
```

Историческое поле `Сумма прибыли с учетом возврата без НДС`:

- без возврата → `Прибыль без НДС`;
- полный возврат → `0`;
- частичный возврат → расчёт из остаточных компонентов прибыли с выделением НДС.

### 3.8. SR и LR

```text
SR = Итого оплачено клиентом,
если схема = Агент поставщика SR

LR = Итого оплачено клиентом,
если схема = Агент поставщика LR
```

### 3.9. Тур

Признак `Да` устанавливается, если:

1. категория `Экскурсия` связана с `Круизом` или `Отелем`;
2. категория — `Круиз`;
3. категория `Отель` связана с `Экскурсией` или `Круизом`;
4. связанные сделки содержат `Круиз` либо сочетание `Экскурсия` + `Отель`.

## 4. Особенности отдельных полей

### `% участия агента в продаже`

Название вводит в заблуждение: в данных встречается формат:

```text
Фамилия Имя=15000.00
```

Рекомендуемый разбор:

```regex
^(.+?)=(-?\d+(?:[.,]\d+)?)$
```

Результат:

- `agent_participant_name`;
- `agent_participation_amount`.

### `Тип карты`

Поле зависит от финансовой карты:

- при списании — тип карты списания;
- при нескольких списаниях возможны несколько значений;
- оплата по ссылке может приводить к значению `Ссылка`;
- без финкарты может использоваться основная карта клиента.

### `Дата оказания услуги`

Определяется по типу сделки. Для схемы `Сервисный сбор РС ТЛС` исторически использовался день списания аванса; при отсутствии списания значение пустое.

## 7. Правила парсинга HTML-XLS

1. Определять HTML по сигнатуре содержимого, а не доверять расширению `.xls`.
2. Читать заголовки из `<thead>`, строки — из `<tbody>`.
3. Декодировать HTML-сущности.
4. Заменять неразрывные пробелы.
5. Нормализовать пробелы и переносы в заголовках.
6. Хранить ID строками.
7. Числа разбирать с запятой/точкой и возможным минусом.
8. Даты приводить к ISO.
9. Не пересчитывать готовые поля без необходимости; хранить исходное и проверочное значение.
10. Проверять уникальность номера сделки.

## 8. Роль после перехода на Б24 NEW

Старый УО рекомендуется использовать:

- как эталон для проверки формул новой выгрузки;
- для исторической загрузки периодов, где нет Б24 NEW;
- для контроля состава полей.

Не рекомендуется строить новый процесс на постоянной выгрузке УО: расчёты скрыты на стороне Б24, формат является HTML под видом XLS, а логика может меняться без изменения структуры файла.
