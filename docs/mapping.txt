# Маппинг полей 1С, Б24 УО, Б24 NEW и Сводного отчёта

## 1. Назначение

Документ задаёт канонические соответствия для парсера и описывает, как получить поля ручного `Сводный.xlsx` из:

- `1C 14.07.xlsx`;
- старого Б24 `Универсальный отчёт.xls`;
- нового сырого `Б24 NEW.xlsx`.

Обозначения:

- `Б24 УО` — старый Универсальный отчёт;
- `Б24 NEW` — лист `Отчет по сделкам`;
- `—` — прямого поля нет;
- `lookup` — значение получается из отдельного справочника;
- `COALESCE(x, 0)` — пустой компонент для арифметики принимается равным нулю, при этом исходное пустое значение сохраняется.

## 4. Формулы Б24 NEW

Для строки `n` листа `Отчет по сделкам`:

### 4.1. Сумма продажи

```excel
=BDn
```

```text
sales_amount = total_client_pay
```

### 4.2. Прибыль

```excel
=ATn+AXn+AZn
```

```text
profit =
    additional_benefit
    + service_fee
    + commission
```

### 4.3. Прибыль без НДС

```excel
=ATn+(AXn+AZn)/1.22
```

```text
profit_ex_vat =
    additional_benefit
    + (service_fee + commission) / vat_factor
```

Для 2026 года `vat_factor = 1,22`.

### 4.4. Продажа после возврата

```excel
=BDn-BFn
```

```text
sales_amount_after_refund =
    total_client_pay
    - client_refund_amount
```

### 4.5. Прибыль после возврата

```excel
=ATn+AXn+AZn-BOn-BMn-BIn+BUn+BWn
```

```text
profit_after_refund =
    additional_benefit
    + service_fee
    + commission
    - additional_benefit_refund
    - service_fee_refund
    - commission_refund
    + rstls_return_fee
    + rstls_return_penalty
```

### 4.6. Прибыль после возврата без НДС

```excel
=(ATn-BOn)+(AXn-BMn+AZn-BIn+BUn+BWn)/1.22
```

```text
profit_after_refund_ex_vat =
    (additional_benefit - additional_benefit_refund)
    + (
        service_fee - service_fee_refund
        + commission - commission_refund
        + rstls_return_fee
        + rstls_return_penalty
      ) / vat_factor
```

### 4.7. Удержал поставщик

```text
supplier_retained =
    supplier_return_fee
    + supplier_return_penalty
```

Для NEW:

```excel
=BQn+BSn
```

Показатель не включается в прибыль РС ТЛС.

### 4.8. SR и LR

```text
if normalize(fin_card_scheme) = SR:
    sr = total_paid_by_client
else:
    sr = 0

if normalize(fin_card_scheme) = LR:
    lr = total_paid_by_client
```

### 5.4. Нормализация агента

```text
agent_key = exact_lookup(source, normalize_spaces(agent_raw))
agent_display = agents[agent_key].name_display
agent_team = agents[agent_key].team
```

Если алиас не найден, значение должно попасть в реестр `unknown`, а не автоматически объединяться с похожим ФИО.

### 5.5. Нормализация категории

Приоритет для 1С:

```text
category_normalized =
    lookup(related_service_type)
```

Для Б24:

```text
category_normalized =
    lookup(category)
```

### 5.6. Тип запроса для 1С

```text
request_type = lookup(category_to_request_type, category)
            ?? lookup(category_to_request_type, related_service_type)
```

Примеры:

- `Air Tickets` / `Авиабилет` → `Travel`;
- `Rail Tickets` / `ЖД билет` → `Travel`;
- `Retail` → `Lifestyle`;
- ресторанные и событийные категории → `Lifestyle`.

### 5.7. Воронка

В ручном отчёте воронка формируется через внешний справочник статусов. Рекомендуемая каноническая логика:

```text
if deal_result = "Успех":
    funnel = "УСПЕХ"
else if deal_result = "Проиграна"
     or deal_status in configured_lost_statuses:
    funnel = "ОТКАЗ"
else:
    funnel = "В ПРОЦЕССЕ"
```

Конкретный список статусов должен храниться в версионируемом справочнике, а не во внешней Excel-ссылке.

### 5.8. Тур

```text
tour = "Да", если:
    category = "Круиз"
    OR category = "Экскурсия"
       AND related_deals содержат Круиз или Отель
    OR category = "Отель"
       AND related_deals содержат Экскурсию или Круиз
    OR related_deals содержат Круиз
    OR related_deals одновременно содержат Экскурсию и Отель
иначе "Нет"
```

## 6. Ключи связи 1С ↔ Б24

| Приоритет | Б24 | 1С | Алгоритм | Надёжность/ограничение |

| 1 | `Лид` | `Кейс` | `000002{lead_id}` в тексте кейса | Лучший доступный ключ; исторически около 52% покрытия |

## 8. Правила агрегации

1. Одна строка 1С — операция/услуга; одна строка Б24 — сделка.
2. `COUNT(*)` по объединённым источникам не является количеством продаж.
3. Количество счетов: `COUNT(DISTINCT order_no)`.
4. Количество обращений: `COUNT(DISTINCT deal_no)`.
5. Продажи по 1С: `SUM(sales_amount)` с отрицательными возвратами.
6. Продажи Б24 после возврата: `SUM(total_client_pay-client_refund_amount)`.
7. Если одна продажа найдена и в 1С, и в Б24, в финансовый итог включается один выбранный источник, обычно 1С.
8. Суммы `SR`, `LR`, способы оплаты и компоненты прибыли нельзя повторно добавлять к `Сумма продажи`.

## 9. Контроль качества маппинга

Перед загрузкой проверять:

- обязательные заголовки и лист;
- дубли заголовков;
- порядок позиционных полей 1С;
- уникальность `deal_no` Б24;
- долю пустых финансовых полей;
- неизвестных агентов, категорий и статусов;
- `client_refund_amount > total_client_pay`;
- расхождение рассчитанных полей NEW и готовых полей УО на общем периоде;
- изменение ставки НДС;
- наличие валютных сделок;
- временной срез выгрузки;
- число строк на один счёт;
- процент связавшихся 1С↔Б24 записей.

## 10. Подтверждение формул на данных

Сопоставление `Б24 NEW.xlsx` и `Универсальный отчёт.xls`:

| Проверка | Совпало | Доля |
| --- | ---: | ---: |
| Общих ID | 2 182 | — |
| Продажа после возврата | 2 167 | 99,31% |
| Прибыль после возврата | 2 159 | 98,95% |
| Прибыль без НДС по уточнённой формуле | 2 154 | 98,72% |

Пример ID `36149`:

```text
Продажа = 46 200
Комиссия = 4 200
Прибыль без НДС = 4 200 / 1,22 = 3 442,62
```

Пример ID `36150`: продажа и комиссия полностью возвращены, поэтому продажа и прибыль после возврата равны нулю.

## 11. Критические ограничения

1. Сводные таблицы `Сводный.xlsx` содержат больше исторических записей в кэше, чем видно на детальных листах.
2. Refresh текущей книги может удалить исторические итоги.
3. Формулы листа кейсов зависят от недоступных внешних справочников.
4. Текущий коэффициент `1,22` нельзя применять ко всем историческим периодам.
5. Простая формула `Комиссия + Сервисный сбор` неполна: она теряет дополнительную выгоду.
6. `ID` сделки Б24, `Лид`, `Кейс` 1С и `Заказ` 1С — разные сущности.
7. Пустое финансовое значение и ноль имеют разный смысл.
8. Для автоматизации необходимо версионировать маппинг, справочники и формулы вместе с датой вступления правил в силу.
