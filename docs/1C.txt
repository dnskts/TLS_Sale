# Выгрузка 1С

## 1. Общая характеристика

Файл: `1C 14.07.xlsx`.

| Параметр | Значение |
| --- | --- |
| Лист | `TDSheet` |
| Диапазон | `A1:AS7310` |
| Строк | 7 310, включая заголовок |
| Строк данных | 7 309 |
| Колонок | 45 |
| Заголовок | строка 1 |
| Формулы | нет |
| Сводные таблицы | нет |
| Excel-таблицы | нет |
| Объединённые ячейки | нет |

Единица строки — финансовая операция или позиция услуги. Один счёт может занимать несколько строк. Поэтому нельзя считать количество заказов простым количеством строк и нельзя удалять повторяющиеся номера счетов без явной агрегации.

## 3. Ключевые идентификаторы

### 3.1. Кейс

Из текста `Кейс` извлекается цифровая часть:

```regex
000002(\d+)
```

Пример:

```text
Кейс 00000210250 от 10.07.2026 16:59:38
→ case_id = 10250
```

Связь с Б24 преимущественно строится через `Лид`:

```text
case_id 1С = lead_id Б24
```

Либо по наличию `000002{lead_id}` в тексте кейса.

### 3.2. Заказ/счёт

Из поля `Заказ` извлекается:

```regex
(0000-\d+)
```

Пример:

```text
Счет клиенту(Продажа) 0000-057583 от 10.07.2026 19:57:57
→ order_no = 0000-057583
```

### 3.3. ID клиента

Для сверки с Б24 используются:

1. `I d CRM`;
2. `ID клиента из кейса`;
3. нормализованное ФИО — только как вспомогательный, ненадёжный ключ.

Все ID следует хранить строками, чтобы не терять ведущие нули и буквенные значения.

## 4. Финансовые показатели

### 4.1. Сумма продажи

`Сумма продажи` — фактическая сумма строки операции. Отрицательное значение означает возврат и не должно отбрасываться.

```text
is_refund = sales_amount < 0
```

### 4.2. Прибыль

Выгрузка уже содержит готовые поля:

- `Прибыль`;
- `Прибыль без НДС`;
- компоненты НДС.

Для управленческого дашборда рекомендуется использовать готовую `Прибыль без НДС` из 1С, а не пересчитывать её по упрощённой формуле Б24.

### 4.3. SR и LR

`SR` и `LR` — обороты по соответствующим схемам реализации. Их нельзя суммировать с `Сумма продажи` как независимые продажи: это аналитические составляющие той же операции.

## 5. Гранулярность и агрегация

Один счёт может включать:

- несколько услуг;
- несколько поставщиков;
- отдельные строки комиссии и сбора;
- частичный возврат;
- разные даты реализации.

Безопасный пример: счёт `0000-057628` представлен несколькими строками, в том числе суммами продажи `193,16` и `25 583`.

Рекомендуемые уровни:

| Задача | Группировка |
| --- | --- |
| Финансовый факт | все строки без дедупликации |
| Количество счетов | `COUNT(DISTINCT order_no)` |
| Количество кейсов | `COUNT(DISTINCT case_id)` |
| Продажи по счёту | `SUM(sales_amount)` по `order_no` |
| Продажи по клиенту | `SUM(sales_amount)` по ID клиента |

## 6. Нормализация

### 6.1. Агент

Имена агентов 1С обычно записаны латиницей, а в Б24 — кириллицей. Требуется справочник:

```text
agent_key
name_1c
name_bitrix
name_display
team
is_active
```

Сопоставление должно быть точным по алиасам после:

- удаления пробелов по краям;
- замены неразрывных пробелов;
- унификации повторных пробелов.

### 6.2. Категория

Для дашборда приоритетнее `Связанный вид услуги`, поскольку он уже содержит русскую бизнес-категорию. Поле `Категория` полезно как дополнительный исходный классификатор.

Примеры:

| Категория 1С | Связанный вид услуги | Нормализованная категория |
| --- | --- | --- |
| `Air Tickets` | `Авиабилет` | `Авиа` |
| `Accommodation Hotels TR` | `Отельный билет` | `Отель` |
| `Rail Tickets` | `ЖД билет` | `Ж.д.` |
| `VIP service at the airport` | `ВИП Обслуживание` | `Вип-сервис` |
| `Tickets` | `Билеты на мероприятие` | `Билеты на мероприятие` |

## 7. Правила парсинга

1. Определять формат по обязательным заголовкам: `Дата операции`, `Агент`, `Поставщик`, `Сумма продажи`.
2. Выбирать лист строго по имени `TDSheet`.
3. Первые две колонки имеют одинаковый заголовок, поэтому читать их по позиции.
4. Проверять число и порядок колонок до загрузки.
5. Обрезать пробелы, но не менять регистр исходных значений.
6. Пустые финансовые значения хранить как `null`, не как `0`.
7. Числа разбирать с учётом запятой и точки как десятичного разделителя.
8. Даты приводить к ISO `YYYY-MM-DD`; исходное значение при необходимости сохранять отдельно.
9. Не удалять отрицательные суммы.
10. Не дедуплицировать строки по счёту.
11. Сохранять номер исходной строки для диагностики.

## 8. Контроль качества

При каждой загрузке проверять:

- наличие листа и обязательных колонок;
- точное количество/порядок позиционных колонок;
- долю строк без агента, клиента, счёта и суммы;
- количество возвратов;
- баланс продаж и возвратов;
- неизвестных агентов и категорий;
- дубли строк по полному набору исходных значений;
- максимальное число строк на один счёт;
- диапазон дат;
- изменение структуры относительно предыдущей выгрузки.

## 9. Роль в автоматизированном отчёте

1С следует считать основным источником финансового факта:

- продажи;
- возвраты;
- прибыль без НДС;
- дата операции и реализации;
- поставщик;
- схема реализации;
- способы оплаты.

Б24 дополняет факт атрибутами воронки, сделки и обращения. Если одна и та же продажа присутствует в обоих источниках, её нельзя дважды включать в общий оборот.
