# Выгрузка Б24 NEW

## 1. Общая характеристика

Файл `Б24 NEW.xlsx` — новая сырая выгрузка сделок Битрикс24. В отличие от старого Универсального отчёта, она почти не содержит вычисляемых полей: финансовые компоненты выгружаются отдельно, а итоговые продажи и прибыль должны рассчитываться после парсинга.

### Листы

| Лист | Диапазон | Содержание |
| --- | --- | --- |
| `Лист1` | `A1` | Текст `какой то набор формул`; реальных формул нет |
| `Отчет по сделкам` | `A1:BX2318` | 2 317 строк сделок и 76 колонок |

На листе данных нет формул, объединений, сводных или структурированных Excel-таблиц. Финансовые значения `AR:BX` сохранены как исходные числовые данные.

Единица строки — сделка Б24.

## 3. Подтверждённые расчётные поля

Формулы восстановлены сравнением новой выгрузки со старым Универсальным отчётом по 2 182 общим ID.

### 3.1. Сумма продажи

```text
Сумма продажи = Всего к оплате Клиентом
```

```excel
=BD2
```

Важно: `Сумма оплаты` (`AC`) и `Всего к оплате Клиентом` (`BD`) имеют разный смысл. Для аналога поля `Сумма продажи` старого УО используется `BD`.

### 3.2. Прибыль

```text
Прибыль =
    Дополнительная выгода
    + Сервисный сбор
    + Комиссия
```

```excel
=AT2+AX2+AZ2
```

`Нетто` и `Всего к оплате Поставщику` в эту восстановленную формулу не входят.

### 3.3. Прибыль без НДС

```text
Прибыль без НДС =
    Дополнительная выгода
    + (Сервисный сбор + Комиссия) / 1,22
```

```excel
=AT2+(AX2+AZ2)/1.22
```

Формула подтверждена совпадением с историческим УО примерно в 98,72% общих сделок. Остаточные расхождения похожи на различия времени формирования снимков.

Ставка `1,22` относится к 2026 году. В промышленной реализации коэффициент должен определяться по дате и применимой ставке НДС.

### 3.4. Сумма продажи после возврата

```text
Сумма продажи после возврата =
    Всего к оплате Клиентом
    - Сумма возврата клиенту
```

```excel
=BD2-BF2
```

Совпадение со старым УО: 2 167 из 2 182 общих сделок, около 99,31%.

### 3.5. Прибыль с учётом возврата

```text
Прибыль после возврата =
    Дополнительная выгода
    + Сервисный сбор
    + Комиссия
    - Возврат дополнительной выгоды
    - Возврат сервисного сбора РС ТЛС
    - Возврат комиссии
    + Сбор РС ТЛС за возврат
    + Штраф РС ТЛС за возврат
```

```excel
=AT2+AX2+AZ2-BO2-BM2-BI2+BU2+BW2
```

Совпадение со старым УО: около 98,95%.

Сбор и штраф поставщика (`BQ`, `BS`) не являются прибылью РС ТЛС и в формулу не входят.

### 3.6. Прибыль после возврата без НДС

```text
Прибыль после возврата без НДС =
    (Дополнительная выгода - Возврат дополнительной выгоды)
    + (
        Сервисный сбор - Возврат сервисного сбора
        + Комиссия - Возврат комиссии
        + Сбор РС ТЛС за возврат
        + Штраф РС ТЛС за возврат
      ) / 1,22
```

```excel
=(AT2-BO2)+(AX2-BM2+AZ2-BI2+BU2+BW2)/1.22
```

## 4. Примеры проверки

### ID 36149

```text
Сумма продажи: 46 200
Комиссия: 4 200
Прибыль без НДС: 4 200 / 1,22 = 3 442,62
```

### ID 36150

Продажа и комиссия полностью возвращены. После применения возвратных компонентов:

```text
Сумма продажи после возврата = 0
Прибыль после возврата = 0
```

## 5. Даты

Для разных задач нужны разные даты:

| Задача | Поле |
| --- | --- |
| Воронка и обращения | `Дата создания` |
| Оказанные услуги | `Дата оказания услуги` |
| Период услуги | `Дата начала` / `Дата окончания` |
| Продажи | в выгрузке нет однозначного аналога старой `Дата оплаты Клиентом`; использовать согласованную бизнес-дату |

Не следует молча подменять отсутствующую дату оплаты датой создания. Если fallback разрешён, сохранять флаг `date_fallback_used`.

## 6. Связи

| Назначение | Поле Б24 NEW | Соответствие |
| --- | --- | --- |
| Сделка | `ID` | Номер сделки старого УО |
| Кейс 1С | `Лид` | Числовая часть `Кейс 000002...` |
| Клиент | `ID клиента` | `I d CRM` или `ID клиента из кейса` 1С |
| Связанные сделки | `Связанные сделки` | Дополнительная связь между сделками |

`ID` сделки нельзя записывать в поле `case_raw`: это разные идентификаторы. Для канонической модели нужны отдельные `deal_no`, `lead_id` и `case_id`.

## 7. Правила парсинга

1. Определять профиль по заголовкам `ID`, `Ответственный`, `Результат сделки`, `Всего к оплате Клиентом`, `Комиссия`, `Сервисный сбор`.
2. Читать лист `Отчет по сделкам`, а не `Лист1`.
3. Сопоставлять колонки по нормализованному заголовку, не по позиции; буквы приведены для контроля формул.
4. Хранить исходные финансовые компоненты до расчёта итогов.
5. Пустое значение сохранять как `null`; при арифметике финансовых компонентов применять согласованное правило `COALESCE(value, 0)`.
6. Хранить исходную и нормализованную валюту.
7. Не применять формулы к полям «в валюте» без явного правила конвертации.
8. Сохранять все сделки для воронки; для финансового среза отдельно фильтровать успешные сделки и возвраты.
9. Не считать поле `% участия агента` процентом без проверки формата.
10. Фиксировать версию формул и ставку НДС.

## 8. Контроль качества

При загрузке проверять:

- уникальность `ID`;
- наличие ответственного, клиента, результата и стадии;
- допустимые значения валюты;
- отрицательные исходные компоненты;
- возврат, превышающий исходную сумму;
- ненулевую продажу при нулевых финансовых компонентах;
- расхождение `Сумма оплаты` и `Всего к оплате Клиентом`;
- неизвестные стадии, категории, агентов;
- долю сделок без даты оказания услуги;
- изменение числа или названий колонок.

## 9. Роль в дашборде

Б24 NEW рекомендуется использовать вместо старого УО как:

- источник всех сделок для воронки;
- источник клиента, категории, канала, стадии и ответственного;
- оперативный источник компонентов продаж и прибыли;
- источник возвратов до появления факта в 1С.

Для закрытого финансового факта приоритет должен оставаться у 1С. Б24 и 1С нельзя складывать как два независимых потока продаж без дедупликации/выбора приоритетного источника.
