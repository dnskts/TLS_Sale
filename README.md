# Дашборд продаж РС ТЛС

Offline-дашборд для анализа продаж сотрудников по выгрузкам **1С** и **Битрикс24**.  
Работает в закрытой сети без доступа в интернет и без пароля.

## Требования

- Python 3.11+
- PHP (для точки входа `index.php`, опционально)
- Windows / Linux в локальной сети

## Полный цикл работы

### 1. Виртуальное окружение и зависимости

```bash
python -m venv .venv
```

Windows:

```bash
.venv\Scripts\activate
pip install -r requirements.txt
```

Linux:

```bash
source .venv/bin/activate
pip install -r requirements.txt
```

Все пакеты ставятся локально (Dash, Plotly, pandas, openpyxl) — **без CDN**.

### 2. Входные данные

Скопируйте файлы в каталог `input/`:

- `input/1C.xlsx` — выгрузка 1С (лист `TDSheet`)
- `input/Битрикс.xlsx` — выгрузка Битрикс24 (лист `Битрикс`)

Формат полей описан в [`format_spec.txt`](format_spec.txt).

### 3. Справочник агентов (`settings.json` → `agents`)

**Единственный источник правды** по соответствию имён — ключ `agents` в `settings.json`.  
Excel-справочник в runtime **не используется**. Предпочтительно редактировать через вкладку **«Настройки»** в дашборде.

#### Настройка агентов через UI

1. Откройте вкладку **«Настройки»** в дашборде.
2. Найдите агента или нажмите **«Добавить агента»**.
3. Укажите имена **точно как в выгрузках** — по одному алиасу на строку в полях «Алиасы 1С» / «Алиасы Битрикс».
4. **«Записать в список»** → **«Сохранить изменения»** — запись в `settings.json` (резервная копия в `data/backups/`).
5. **«Применить к данным (пересобрать БД)»** — пересчёт привязки продаж к агентам в отчётах.

Смена фамилии = **один** агент с несколькими строками в `names_1c` / `names_bitrix`, а не две карточки.  
У существующих агентов **не меняйте** `agent_key` — поле заблокировано при редактировании.  
Удаление агента не удаляет строки продаж — они станут `unknown:…` до перепривязки имён.

Ручное редактирование JSON тоже возможно, но UI предпочтителен.

Пример записи:

```json
{
  "agent_key": "bobkov_sergey",
  "name_display": "Бобков Сергей",
  "names_1c": ["Sergey Bobkov"],
  "names_bitrix": ["Бобков Сергей"],
  "team": "Centurion",
  "is_active": true
}
```

| Поле | Назначение |
|------|------------|
| `agent_key` | Стабильный идентификатор (латиница, не менять при смене фамилии) |
| `name_display` | Отображаемое имя в UI |
| `names_1c` | Точные значения поля **Агент** из 1С (после trim) |
| `names_bitrix` | Точные значения **Ответственное лицо** из Битрикс |
| `team` | Команда для фильтров и рейтингов |
| `is_active` | `true` — участвует в фильтрах по умолчанию; `false` — скрыт, пока не включён чекбокс «Показать неактивных» |

#### Как добавить нового агента

1. Откройте `settings.json`, найдите массив `"agents"`.
2. Добавьте объект с уникальным `agent_key`, `name_display`, `names_1c`, `names_bitrix`, `team`, `"is_active": true`.
3. Запустите `python -m parser.pipeline` (или кнопку «Обновить данные» в UI).
4. Проверьте вкладку **Детализация** — агент не должен оставаться в списке «Неизвестные агенты».

#### Смена фамилии / несколько написаний имени

Не меняйте `agent_key`. Добавьте **второй alias** в массив:

```json
"names_1c": ["Ivanov Ivan", "Ivanov I."],
"names_bitrix": ["Иванов Иван", "Иванов И."]
```

Сопоставление — **только точное совпадение** (после trim), без эвристик.

#### Уволенный сотрудник

```json
"is_active": false
```

После перезагрузки pipeline агент исчезнет из фильтров и рейтингов по умолчанию. Для просмотра истории включите «Показать неактивных» в боковой панели.

#### Неизвестные агенты

Имена, не найденные в справочнике, получают ключ `unknown:{raw}` и попадают в `data/last_load.json` → `top_unknown_agents`.  
В UI — группа «Не в справочнике» (чекбокс в фильтрах).

### 4. Загрузка данных (ETL)

```bash
python -m parser.pipeline
```

Создаёт:

- `data/dashboard.db` — таблицы `operations_1c`, `deals_bitrix`, `sales_unified`, `agents_dim`
- `data/last_load.json` — метаданные, счётчики, предупреждения, неизвестные агенты

### 5. Запуск дашборда

```bash
python -m app.main
```

По умолчанию: `http://127.0.0.1:8050` (см. `settings.json` → `app`).

### 6. Точка входа через PHP

Если на сервере настроен PHP, откройте `index.php`:

- если Dash слушает порт — редирект на `dash_url`;
- иначе — страница с инструкцией по запуску.

## Вкладки дашборда

| Вкладка | Данные | Примечание |
|---------|--------|------------|
| Обзор | `sales_unified` | KPI, динамика, топы |
| Агенты и команды | `sales_unified` | Рейтинги, таблицы |
| Структура продаж | `sales_unified` | Категории, каналы и т.д. |
| Воронка Битрикс | `deals_bitrix` | **Все** сделки; период по `deal_created_at` |
| Детализация | `sales_unified` + диагностика из `last_load.json` | Строки продаж, предупреждения парсера |
| Настройки | `settings.json` → `agents` | Редактор справочника агентов |

## Бизнес-правила (инварианты)

1. **1С и Битрикс — независимые продажи.** KPI = сумма обоих источников, без дедупликации.
2. **Прибыль** везде = `profit_ex_vat`.
3. **Битрикс в продажах (sales_unified):** только `deal_result == "Успех"`.
4. **Даты продаж:** 1С — `date_operation`; Битрикс — `client_paid_at`, fallback `deal_created_at`.
5. **Агент 1С:** поле `agent`; `issuing_agent` не в метриках.
6. **Агент Битрикс:** `responsible_person`.
7. **Маппинг агентов** — только из `settings.json` → `agents`.
8. **Фильтры по умолчанию:** только `is_active: true`.
9. **Два «Дата операции» в 1С** — различать по индексу колонки.
10. **Воронка Битрикс** — по **всем** сделкам `deals_bitrix`, период по дате создания.

## Конфигурация (`settings.json`)

| Раздел | Назначение |
|--------|------------|
| `app` | Заголовок, host, port, URL дашборда |
| `paths` | Пути к input, SQLite, метаданным загрузки |
| `sheets` | Имена листов Excel |
| `metrics` | Поля дат, прибыли, фильтр успеха Битрикс |
| `defaults` | Период, источник, показ неактивных агентов |
| `department_map` | Маппинг команд 1С → отображение |
| `agents` | Справочник агентов |
